# 見本画像によるカテゴリ判定

「見本カテゴリ」タブでカテゴリ名、目に見える判定基準、見本画像1〜3枚を
登録します（最大5カテゴリ）。たとえば「ポンプ容器」「上部にポンプが付いた
容器が写っている」と入力し、対象がはっきり写った写真を選びます。
見本は独立した縮小JPEGとして保存され、ライブラリの素材削除に影響されません。

登録後、画面の「ライブラリで再取り込みへ」から「再取り込み」を実行します。
判定対象と見本をGeminiへ一緒に送信し、カテゴリごとに次の結果を保存します。

| 結果 | 検索用タグ |
|---|---|
| 該当 | カテゴリ名を追加 |
| 非該当 | 追加しない |
| 判定保留 | 追加しない |

画像カードの「見本カテゴリのAI判定」で結果と理由を確認できます。該当した
カテゴリ名はキーワード検索・既存APIのtagsフィルタで利用できます。
手動タグ、一般のAIタグ・説明、商品コードとは別に保存します。
同じ商品・同じSKUの保証、人物の同定、領域の囲み表示には使いません。

## 更新と再試行

- 登録・削除すると、全画像のカテゴリ判定をいったん消します。画面の案内に
  従って再取り込みしてください。編集は削除→再登録で行います。
- 取り込み中のカテゴリ変更は409で拒否します。終了後に再実行してください。
- 成功した判定は、見本と対象画像の内容が変わらなければ再利用します。
  非該当・判定保留も成功した観察として再利用します。
- 対象画像はSHA-256で確認するため、同じファイルサイズでも異なる内容なら
  再判定します。判定失敗・上限到達でも古い該当タグは残しません。
- 失敗や上限で見送った画像は次の再取り込みで再試行します。元画像と検索用
  ベクトルは利用可能です。見本がない場合・動画の場合は判定しません。

## 設定・費用

既存の `IMAGE_ANNOTATION_BACKEND=gemini` と `GOOGLE_CLOUD_PROJECT`、モデルと
リージョン設定、実行サービスアカウントを利用します。ローカルの既定はoff。
無効な環境でも見本は登録できますが判定は実行されず、画面に案内が出ます。
Google Cloudの追加リソース作成や学習は不要です。

`CATEGORY_MAX_PER_IMPORT` は追加の分類リクエスト上限（既定50、正の整数）。
WebサービスとImport Jobの両方へ同じ値を設定します。画面にはWebサービスの
設定値が表示されるため、Jobだけ変えると表示と実際の上限が一致しません。
一般のAIタグ生成の上限 `IMAGE_ANNOTATION_MAX_PER_IMPORT` とは別です。
既定では新規画像50枚に対して最大50回の一般タグ生成＋50回のカテゴリ判定。
検索時にはGeminiを呼び出しません。カテゴリ判定1回には全見本も入力される
ため、一般の1画像タグ生成より入力トークンが多くなります。

見本は1枚30MiB/4000万画素まで受け付け、512px以下・256KiB以下のJPEGとして
SQLiteに保存します。最大15枚の見本と対象を1リクエストにまとめ、送信JSONは
8MiB以下、タイムアウト45秒、最大出力2048トークン。自動リトライなし。
見本を含むSQLiteは既存のGCS同期に保存され、既存IAPの内側からのみ表示します。
再利用確認は画像を読み取るため、モデル呼び出しを省略した場合もストレージ
読み出し・転送の費用は発生し得ます。

[Google公式の複数画像入力サンプル](https://docs.cloud.google.com/vertex-ai/generative-ai/docs/samples/googlegenaisdk-textgen-with-multi-local-img)
に沿ったinlineDataの複数入力です。これは見本に基づく推論であり、専用モデル
の学習や精度保証ではありません。実際の業務カテゴリには代表例・紛らわしい
非該当例・隠れた対象を含めて確認してください。
